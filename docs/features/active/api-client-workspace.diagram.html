API Client Workspace Model

Why the API Client feels off next to Bruno, and the two-slice plan: surface where data lives (A), then make collections live in folders you own (B).

The problem — three disconnected worlds

Bruno's model — a collection is a folder; requests are files; git is just git on that folder — already exists in Core. It was never switched on. Slice B is activation, not invention.

Slice A — clarity pass

Where data lives
  • Workspace footer: Internal store · collections.json + reveal + copy
  • Settings → API Client gains Reveal (new reveal_in_explorer Tauri command)
  • Labeled import buttons replace bare icons
Honest imports
  • File/Bruno tabs say exactly what happens: one-way copy into the internal store
  • Success summary names the destination directory
  • cURL dialog: live multi-request preview, warnings list, labeled destination
Better cURL
  • Multi-command paste → N requests
  • ^ continuations, -F form fields, -b/-A/-e headers
  • Unknown flags surface as warnings — no more silent drops
Git honesty
  • Panel explains: app saves go to the internal store, not this repo
  • Bridge to Slice B: link the repo instead of staring at it

Slice B — linked roots (the Bruno model)

Why it holds up

ChoiceReason
linkedRoots[] beside collections[] in the store responseInternal PUT contract untouched; origin is explicit at flatten time; one fetch hydrates both worlds.
Per-node endpoints, not whole-root PUTFile-per-request model maps 1:1 onto LinkedCollectionFileService; small writes, real conflict stamps — no new blob semantics.
Import writes .swebreq.json, not .bruLinked roots are SwebKit's format. Bruno folders import cleanly into them; .bru write-back is its own sync feature.
GitPanel stays genericA linked root inside a repo is just a repo + apiSubpath — no second git UI. Root headers deep-link into it.

Trade-offs

  • No fs-watching. External edits are caught at save (content stamp → 409) or via manual Reload — deliberate v1 line.
  • Two storage kinds in one tree. Mitigated by section headers with path/reveal and origin-aware routing; the PUT never mixes them.
  • AllowedRoots grant. Git ops need the repo dir granted via the OS picker; picking the repo root as the linked folder keeps this seamless. Inner-folder picks still work for file sync — git on an ancestor repo may be ungranted and reports cleanly.

Rollout

  1. A lands first — visibility + imports + honesty on the current store model; no behavior risk.
  2. B: sidecar endpoints + store merge — dormant Core activated; agent tools see linked collections for free.
  3. B: workspace UI — sections, origin routing, conflict UX, env routing, import destination, git badges.
  4. Follow-ups — Bruno write-back, fs-watch, move-between-sources, OpenAPI import.
