Service Bus — ribbon layout, filter chips, scheduled state

The stacked toolbar + overflow "Actions" menu collapsed ~20 controls into three rows of undifferentiated buttons. This change groups them into a compact four-tab ribbon, makes active filters permanently visible as chips, and promotes Scheduled to a first-class message state alongside Active and DLQ.

Decisions worth knowing

  • Scheduled rides the ordinary peek — the SDK has no scheduled-only listing; the view filters the active window by stamp, and load-more + footer compare against ScheduledMessageCount.
  • Purge keeps scheduled messages — it emulates a receive-delete loop and receivers can't touch unfired schedules; the ribbon disables Purge on the scheduled view and says why.
  • Chips bar lives outside the ribbon — collapsing the ribbon can never hide that the list is narrowed.
  • All ribbon testids preserved from the old toolbar/menu — e2e only gained a tab click.
  • Saved filters unchanged — new operators and the min,max range encoding are additive inside the existing rule shape.
