SwebOS skin — SwebKit × SwebOS design family

SwebKit adopts the SwebOS design system: shared semantic tokens, shared shell metrics, and the two approved families — Aurora and Clay — each in light and dark. The nine bespoke palettes retire; a legacy bridge keeps every existing component working unchanged.

Theme consolidation

Aurora light
DOM: :root · id light
Aurora dark
DOM: .dark · id dark
Clay light
DOM: .clay · id clay
Clay dark
DOM: .clay.dark · id clay-dark

Retired: fancy, fathom-*, letterpress-*, cascade-*. Stale persisted ids map to the nearest Aurora mode via migrateTheme(); light/dark keep meaning so most settings migrate silently.

Shell — current vs SwebOS

Before
  • Sidebar 224px / 56px collapsed, solid accent nav pills
  • Top bar ≥56px wrapping row
  • Footer status bar 28px (health, version, env, timezone)
  • Glassmorphism + aurora glows + per-theme signature moves
After
  • Sidebar 232px / 56px, navsel token (soft pill · clay: raised sheet)
  • Top bar 48px: context, env pill, command search, controls
  • No footer — status folds into a top-bar popover
  • Plain cards: surface + hairline + shadow-1, no blur, no glow

Page treatment

  • AKS — rail/table/badge chrome on semantic + state tokens; log viewer untouched (approved as-is).
  • API Client — tree, tab strip, editors, response on shared chrome; layout stays: request/response vertical, response right.
  • Service Bus — ribbon skinned to spec tab look, entity tree + state badges, message list/detail on shared surfaces.
  • State semantics shared with SwebOS: blocked red · needs amber · working blue · waiting violet · queued neutral · done green.
